# Spec: `chemunited-sim` — simulation server

**Status:** in progress  
**Replaces:** previous spec (timeline/dry-run approach — superseded by live execution architecture)

---

## Overview

Two servers are launched from the same project files — a **work-server** (real hardware
execution) and a **sim-server** (this package). Both run the same `Process` subclass.

The sim-server is a **self-contained long-running service**: a project is loaded and
replaced at runtime via HTTP endpoints, with no need to restart the process.

The sim-server supports two simulation modes, selected at `POST /simulation/start`:

```
┌──────────────────────────────────────────────────────────────────────────────────┐
│  chemunited-sim  (single OS process)                                             │
│                                                                                  │
│  FastAPI ─── POST /project/load ──────► ProjectState                            │
│     │          (compile graph,           project_path                            │
│     │           instantiate Process,     Process instance                        │
│     │           store in state)          ComponentData[]                         │
│     │                                    HydraulicGraph                          │
│     │                                                                            │
│     ├─── spawns ──────────────────────► Worker Thread  (loop — always active)   │
│     │                                     ① drain Queue → apply() → resync()    │
│     │                                     ② fire scheduled heap (if due)        │
│     │                                     ③ Worker.step()                       │
│     │                                     ④ clock.advance(dt)                   │
│     │                                     ⑤ [real_time] throttle to wall clock  │
│     │                                                                            │
│     ├─ [mode 1] spawns ────────────────► Workflow Thread(s) [ThreadPoolExecutor]│
│     │                                     Process.run_workflow()                 │
│     │                                     SimClient.put() → queue.put(SimCmd)   │
│     │                                     busy-wait: clock.now() < t0+wait_time │
│     │                                                                            │
│     └─ [mode 2] POST /simulation/command ──────────────► Command Queue          │
│                                                                                  │
│  Shared in-process memory:                                                       │
│    SimClock  │  Command Queue  │  stop_event  │  _workflow_done                 │
│    (ProjectState owns: ComponentData[] + HydraulicGraph + Process)              │
└──────────────────────────────────────────────────────────────────────────────────┘
          │                                                  │
   work-server / UI                                 <execution_id>.db
   /project/load, /start,                        (WAL mode, written by Recorder,
   /stop, /command [mode 2]                       read by Qt GUI directly)
```

## Server state machine

```
NO_PROJECT ──── POST /project/load ────► IDLE
    IDLE    ──── POST /project/load ────► IDLE   (replaces current project)
    IDLE    ──── POST /simulation/start ► RUNNING
    RUNNING ──── POST /simulation/stop ─► IDLE
    RUNNING ──── auto-complete ─────────► IDLE
    RUNNING ──── POST /project/load ────► 409   (rejected — sim in progress)
```

`POST /simulation/start` returns 409 when no project is loaded.

---

## Two simulation modes

### Mode 1 — Workflow simulation (`real_time=False`)

The protocol runs live inside the sim-server via a `SimPlatform` whose clients
busy-wait on `SimClock` instead of `time.sleep()`. Commands generated by the protocol
are enqueued and applied by the Worker Thread. The sim runs at CPU speed — much faster
than real time.

An optional `historical_file` JSON can be provided at `POST /project/load` to
initialise process parameters and component states before the protocol begins.

### Mode 2 — Real-time simulation (`real_time=True`)

No Workflow Thread is spawned. The Worker Thread runs at wall-clock pace (throttled so
`SimClock.t` tracks `time.monotonic()`). Commands arrive at
`POST /simulation/command` from the work-server as it executes them on real hardware.

---

## Architecture — threading model

All state is in-process. Three concurrent actors communicate via two primitives:

| Shared object | Writer | Reader(s) |
|---|---|---|
| `ProjectState` | FastAPI (`POST /project/load`) | FastAPI (`POST /simulation/start`) |
| `SimClock` | Worker Thread | Workflow Thread(s) [mode 1] |
| `Command Queue` (`queue.Queue`) | Workflow Thread(s) or FastAPI | Worker Thread |
| `ComponentData[]` | Worker Thread (via `apply()`) | Worker Thread (via `step()`) |
| `HydraulicGraph` | Worker Thread (via `resync_component()`) | Worker Thread (via `step()`) |
| `stop_event` (`threading.Event`) | FastAPI (`POST /stop`) | Worker Thread, Workflow Thread(s) |
| `_workflow_done` (`threading.Event`) | Workflow Thread | Worker Thread [mode 1] |

`ProjectState` is written only by `POST /project/load` (single-threaded, no simulation
running at that point) and read by `POST /simulation/start` to build the Worker/Workflow.
No lock is needed for `ProjectState` itself because the state machine prevents concurrent
access.

`ComponentData` and `HydraulicGraph` (held inside `ProjectState`) are owned exclusively
by the Worker Thread during a simulation run. The Workflow Thread only enqueues
`SimCommand` objects; the Worker drains and applies them between `Worker.step()` calls.

## Required changes to dependencies

### `chemunited-core` — changes required

**1. `ComponentData.apply()` — change return type from `None` to `PutResult`**

The Worker Thread needs to know about derived follow-up events after each `apply()`
call (e.g. a pump auto-stop scheduled at `volume / rate` seconds from now). The
current `-> None` signature does not carry this information.

New signature:
```python
def apply(self, command: str, **kwargs) -> PutResult:
```

The `PutResult.scheduled` list works identically to the existing infrastructure:
each `ScheduledCommand(dt, command, kwargs)` tells the Worker to fire `command` on
the same component `dt` sim-seconds later.

`sync_internal_state()` **must be called inside `apply()`** — the Worker Thread does
not call it separately. Typical pattern:

```python
# FlowSourceData
def apply(self, command: str, **kwargs) -> PutResult:
    if command == "infuse":
        self.flow_rate = ChemUnitQuantity(kwargs["rate"])
        self.sync_internal_state()
        result = PutResult()
        volume = kwargs.get("volume")
        if volume is not None:
            t_stop = (
                ChemUnitQuantity(volume).to_base_units().magnitude
                / self.flow_rate_si
            )
            result.scheduled.append(ScheduledCommand(dt=t_stop, command="stop", kwargs={}))
        return result
    if command == "stop":
        self.flow_rate = ChemUnitQuantity("0 ml/min")
        self.sync_internal_state()
        return PutResult()
    return PutResult()
```

```python
# ValveComponentData
def apply(self, command: str, **kwargs) -> PutResult:
    if command == "position":
        connect: list[tuple[int, int]] = kwargs.get("connect", [])
        # derive rotor_ports from connect pairs and update
        ...
        self.sync_internal_state()
    return PutResult()
```

`put()` (the pure-computation version) remains unchanged. For the sim, only `apply()`
is called.

**2. `adapter/graph.py` — add `resync_component()`**

After `apply()` + `sync_internal_state()`, `InternalEdge.resistance_override` values
on the `ComponentData` have changed. The compiled `HydraulicGraph` holds separate
`HydraulicEdge` objects whose `resistance_override` fields were copied by value at
compile time and must be propagated:

```python
def resync_component(graph: HydraulicGraph, comp: ComponentData) -> None:
    """Propagate resistance_override from ComponentData into HydraulicGraph.

    Called immediately after ComponentData.apply(). Topology is never changed;
    only edge attributes are written.

    Note: HydraulicNode.boundary is a shared reference (not deep-copied at
    compile time), so flow-source and pressure-control updates propagate
    automatically via sync_internal_state() — no node propagation needed here.
    """
    for (origin, dest), internal_edge in comp.internal_edges.items():
        edge_id = f"{comp.name}.{origin}.{dest}"
        hydraulic_edge = graph.edges.get(edge_id)
        if hydraulic_edge is not None:
            hydraulic_edge.resistance_override = internal_edge.resistance_override
```

**Summary of `chemunited-core` changes:**

| File | Change |
|---|---|
| `components/component.py` | `apply() -> None` → `apply() -> PutResult` |
| `components/flow_source.py` | Implement `apply()` returning `PutResult` |
| `components/valve.py` | Implement `apply()` returning `PutResult` |
| `components/pressure_control.py` | Implement `apply()` returning `PutResult` |
| `components/pressure_regulator.py` | Implement `apply()` returning `PutResult` |
| *(all other concrete components)* | Implement `apply()` returning `PutResult` |
| `adapter/graph.py` *(in chemunited-sim)* | Add `resync_component()` free function |

## Project structure expected by the loader

```
my_project/
├── draw/
│   └── setup.py                ← must define build_draw(platform)
├── protocols/
│   ├── __init__.py             ← must export PROCESSES and CONFIGS dicts
│   ├── main_parameters.py      ← optional; defines MainParameter(BaseModel)
│   └── <ProcessName>.py        ← one file per process; defines CustomProcess + ProcessConfig
└── protocols_hystoric/         ← required
    └── <name>.json             ← historical_file snapshot; defines process sequence

my_project.chemunited           ← ZIP archive (alternative to folder)
```

`protocols/__init__.py` must export:

```python
PROCESSES = {"ProcessName": CustomProcessClass, ...}   # name → Process subclass
CONFIGS   = {"ProcessName": ProcessConfigClass,  ...}  # name → ProcessConfig subclass
```

The loader imports `protocols/__init__.py` and reads `PROCESSES`.

> **Convention — workflow entry node:** `build_workflow()` must define a node named
> `"start"`. `process.run_workflow(start_node="start")` is always called with this name.

### `historical_file` JSON format

Resides at `protocols_hystoric/<name>.json`. Provided optionally in `POST /project/load`;
if omitted, the most recently modified JSON in `protocols_hystoric/` is used.

```json
{
  "main_parameter": { "repetition_ractions": 1 },
  "clean_0": {},
  "React_1": {},
  "clean_2": {}
}
```

- `main_parameter` is consumed by `process.load_parameters()`.
- All other keys follow the pattern `<ProcessName>_<index>`. The integer suffix defines
  execution order. The value is the per-process config kwargs (may be `{}`).
- Parsing: collect all `<name>_<index>` keys, sort by index → execution sequence.
  Example above → `[("clean", {}), ("React", {}), ("clean", {})]`.

## `cli/loader.py` — project discovery

### Discovery order

1. `path` is a directory → use `path/draw/setup.py` and `path/protocols/__init__.py`.
2. `path` is a `.chemunited` ZIP and a same-name sibling folder exists → use sibling
   folder, ignore the ZIP.
3. `path` is a `.chemunited` ZIP, no sibling folder → extract to
   `tempfile.mkdtemp(prefix="chemunited_")` and use from there.

### Process loading

The loader imports `protocols/__init__.py` and reads `PROCESSES: dict[str, type[Process]]`.
Each key is a process name; each value is the concrete `Process` subclass to instantiate.

### Errors raised

| Condition | Exception |
|---|---|
| `path` does not exist | `FileNotFoundError` |
| `path` is not a directory or `.chemunited` | `ValueError` |
| ZIP is not a valid ZIP file | `ValueError` |
| `draw/setup.py` not found after resolution | `FileNotFoundError` |
| `setup.py` does not define `build_draw` | `AttributeError` |
| `protocols/__init__.py` not found | `FileNotFoundError` |
| `protocols/__init__.py` has no `PROCESSES` attribute | `AttributeError` |

## `cli/clock.py` — `SimClock`

```python
import threading

class SimClock:
    def __init__(self) -> None:
        self._t: float = 0.0
        self._lock = threading.Lock()

    def now(self) -> float:
        with self._lock:
            return self._t

    def advance(self, dt: float) -> None:
        with self._lock:
            self._t += dt

    def reset(self) -> None:
        with self._lock:
            self._t = 0.0
```

Created once at server startup, reused across projects and simulation runs.

### `SimClient`

Satisfies `ComponentClientProtocol`. Mode 1 only.

```python
class SimClient:
    def __init__(
        self,
        name: str,
        component: ComponentData,
        clock: SimClock,
        cmd_queue: queue.Queue,
    ) -> None: ...

    def put(self, command: str, *, wait_time: float = 0.0, **kwargs) -> None:
        t0 = self._clock.now()
        self._queue.put(SimCommand(component=self._name, command=command, kwargs=kwargs))
        while self._clock.now() - t0 < wait_time:
            time.sleep(0.0001)

    def get(self, command: str, **kwargs) -> dict | None:
        return self._component.get(command, **kwargs)
```

`get()` delegates to `ComponentData.get()`, enabling feedback-dependent protocol
branching — a key advantage over the previous timeline approach.

```python
sim_platform = Platform({
    name: SimClient(name, component, clock, cmd_queue)
    for name, component in project_state.components.items()
})
```

## `cli/server.py` — FastAPI app

### `ProjectState`

Populated by `POST /project/load`. Replaced atomically (no lock needed — state machine
prevents concurrent writes).

```python
@dataclass
class ProjectState:
    project_path: Path
    processes: dict[str, type[Process]]   # from protocols/__init__.PROCESSES

```

### `SimulationState`

```python
@dataclass
class SimulationState:
    sim_status: SimStatus          # "no_project" | "idle" | "running" | "completed"
    current_t: float
    config: SimConfig
    db_path: Path | None
    project: ProjectState | None   # None until first /project/load
    clock: SimClock
    cmd_queue: queue.Queue

    _workflow_done: Event = field(default_factory=Event)
```

`SimStatus` is a `str` enum: `"no_project"`, `"idle"`, `"running"`, `"completed"`.

### Worker Thread

```python
import heapq, time, queue as _queue

def _worker_thread_fn(
    worker, components, graph, clock, cmd_queue,
    config, stop_event, workflow_done, state, recorder,
):
    scheduled: list[tuple[float, SimCommand]] = []
    wall_t0 = time.monotonic()
    sim_t0 = clock.now()

    try:
        while not stop_event.is_set():

            # 1. Drain immediate command queue
            while True:
                try:
                    cmd = cmd_queue.get_nowait()
                except _queue.Empty:
                    break
                result = components[cmd.component].apply(cmd.command, **cmd.kwargs)
                resync_component(graph, components[cmd.component])
                for s in result.scheduled:
                    heapq.heappush(scheduled, (
                        clock.now() + s.dt,
                        SimCommand(cmd.component, s.command, s.kwargs),
                    ))

            # 2. Fire scheduled events that are now due
            while scheduled and scheduled[0][0] <= clock.now():
                _, sched_cmd = heapq.heappop(scheduled)
                components[sched_cmd.component].apply(sched_cmd.command, **sched_cmd.kwargs)
                resync_component(graph, components[sched_cmd.component])

            # 3. Check t_end
            if config.t_end is not None and worker.t >= config.t_end:
                state.sim_status = SimStatus.IDLE
                return

            # 4. Auto-complete in mode 1: workflow finished + nothing pending
            if (
                not config.real_time
                and workflow_done.is_set()
                and cmd_queue.empty()
                and not scheduled
            ):
                state.sim_status = SimStatus.IDLE
                return

            # 5. Advance simulation
            worker.step()
            state.current_t = worker.t
            clock.advance(config.dt)

            # 6. Real-time throttle (mode 2)
            if config.real_time:
                elapsed_sim = clock.now() - sim_t0
                elapsed_wall = time.monotonic() - wall_t0
                drift = elapsed_sim - elapsed_wall
                if drift > 0.0:
                    time.sleep(drift)

    finally:
        recorder.close()
        if state.sim_status == SimStatus.RUNNING:
            state.sim_status = SimStatus.IDLE
```

### Workflow Thread (Mode 1 only)

def _workflow_thread_fn(process, start_node, stop_event, workflow_done):

## Endpoints

### `POST /project/load`

Loads a project. Compiles the hydraulic graph and imports available process classes.
Replaces any previously loaded project. Rejected if a simulation is running.

**Request body:**

```json
{
  "path": "/path/to/my_project.chemunited"
}
```

`path` must point to a valid project folder or `.chemunited` ZIP.

**Side effects:**

1. Rejects with 409 if `sim_status == "running"`.
2. Runs `load_project(path)` → `build_draw(builder)` + imports `protocols/__init__.py`
   to read `PROCESSES`.
3. Runs `compile_graph(builder.hydraulic_components, builder.edges)`.
4. Stores a new `ProjectState` (with `processes`, `components`, `graph`) on `state.project`.
5. `state.sim_status → "idle"`.

**Response 200:**

```json
{
  "status": "idle",
  "project_path": "/path/to/my_project",
  "components": ["PumpA", "ValveB", "ReactorA"]
}
```

**Response 409:** Simulation currently running — stop it before loading a new project.

**Response 422:** Project path not found or invalid structure.

### `POST /simulation/start`

Starts the simulation. Requires a project to be loaded.

**Request body:**

```json
{
  "execution_id": "run_2025-05-26T14-30-00",
  "dt": 0.1,
  "t_end": null,
  "real_time": false,
  "historical_file": "test_2026-05-15T10-38-00.json"
}
```

All fields except `execution_id` are optional (defaults from `SimConfig`).
`historical_file` is required for mode 1 (`real_time=False`); ignored in mode 2.
Accepts a **filename** (resolved as `<project>/protocols_hystoric/<filename>`) or a
**full path**. If omitted in mode 1, the most recently modified JSON in
`protocols_hystoric/` is used automatically.

**Side effects (in order):**

1. Rejects with 409 if `sim_status == "no_project"` or `"running"`.
2. `db_dir` is created if missing. DB filename: `<execution_id>.db`. WAL mode enabled.
3. `cmd_queue` drained; `clock.reset()`; events cleared.
4. Fresh `Worker` created from `t=0` using `project.graph` and `SimConfig`.
5. Worker Thread started.
6. If `real_time=False`:
   a. Resolve `historical_file` → parse `<ProcessName>_<index>` keys sorted by index
      → `process_sequence` (e.g. `[("clean", {}), ("React", {}), ("clean", {})]`).
   b. Workflow Thread started: iterates `process_sequence`, instantiating and running
      each `Process` in order via `process.run_workflow("start")`.
7. `state.sim_status → "running"`.

**Response 200:**

```json
{
  "status": "running",
  "db_path": "/abs/path/to/simulations/run_2025-05-26T14-30-00.db"
}
```

**Response 409:** No project loaded, or simulation already running.

---

### `POST /simulation/stop`

Aborts the running simulation. Resets to `"idle"`. Partial `.db` kept.

**Response 200:** `{ "status": "idle" }`

**Response 409:** No simulation currently running.

}

**Response 200:** `{ "queued": true }`

**Response 409:** No simulation currently running.

## `cli/main.py` — execution flow

```
parse args ([project], --port, --db)
    └─ resolve db_dir: --db value or ./simulations/
    └─ build SimClock()
    └─ build queue.Queue() as cmd_queue
    └─ build SimulationState(
           sim_status=NO_PROJECT,
           project=None,
           clock=clock,
           cmd_queue=cmd_queue,
           db_dir=db_dir,
       )
    └─ if project arg was provided:
           call _load_project(project_path, historical_file=None, state)
           # equivalent to POST /project/load at startup
    └─ start FastAPI server via uvicorn on localhost:<port>
```

`_load_project()` is the shared implementation used by both the CLI startup path and
the `POST /project/load` endpoint handler, ensuring identical behaviour.

## Out of scope

- `--viscosity` CLI argument.
- Authentication / CORS.
- Markers / synchronisation table in the db.
- Hub patch for valve centre nodes.
- Reaction map loading.
- Multiple processes in sequence.
- `POST /project/unload` — the server can be left in `idle` state indefinitely.
